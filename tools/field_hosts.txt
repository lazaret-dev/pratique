# The servers of tools/mac_field_check.sh (BACKLOG B-06, B-08, B-65). One per line: GROUP HOST[:PORT]
#
#   ok      the TLS handshake must work, the chain must verify, and a GET of / must answer. These are also the chains that
#           `capture` keeps as fixtures, so the list covers RSA and ECDSA leaves, several CAs (Let's Encrypt, Google Trust
#           Services, DigiCert, Sectigo, Amazon, GlobalSign, Cloudflare...), wildcard certificates, and the servers that the
#           consumer of this library (supply-chain tooling) really talks to.
#   refuse  a certificate that must be refused, as a certificate error (expired, self-signed, wrong host, unknown root).
#   ok-tls12, refuse-tls12
#           the same, for servers that speak only TLS 1.2, and judged the same way since the library speaks TLS 1.2 too (BACKLOG
#           B-36). The name only says what to expect in the TLS version that the smoke test writes down for every host.
#   refuse-handshake
#           a server that offers only what the library will not speak (TLS 1.0 or 1.1, CBC, RSA key exchange, finite-field
#           Diffie-Hellman, no encryption): the handshake must fail as a TLS error, never connect (B-36, B-100).
#   revoked a certificate its CA has revoked (the test sites every public CA must run): checked with hard-fail revocation and the
#           library's OCSP and CRL sources, it must be refused as revoked; `capture` takes its chain (which is otherwise valid)
#           and `revocation` its CA's answers, as fixtures that say "revoked" (B-65, B-100).
#
# A third word `no-ems` marks a server that speaks TLS 1.2 without the extended master secret (RFC 7627). The library requires it
# (B-36), so the smoke test expects that handshake to be refused for exactly that reason (PASS), whatever the group; `capture` still
# takes the chain with OpenSSL and `verify` replays it against the library, expecting what the group says of the certificate.
#   info    whatever happens is written down and is neither a pass nor a fail.
#
# Hosts come and go. A host that cannot be reached is SKIPped, and one that has changed what it serves is a thing to look at,
# not necessarily a bug: edit this file freely. Lines starting with # are comments. Written on 2026-10-07; first run the same day
# from an Apple M5 Max on a home network: 41 of the 49 hosts then listed as `ok` connected, and of the 8 others, 6 were badssl.com
# (TLS 1.2 only), one was registry.npmjs.org (also TLS 1.2 only, from that network: a real gap then, closed by BACKLOG B-36), and
# one was a host whose root is not in macOS's /etc/ssl/cert.pem.
