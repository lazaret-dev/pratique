run, with no replacement hosts, dispatch masks, feature lanes or retry loop.
Each VM selects the first CPU in its allowed affinity and uses that same live
pinned CPU for probes, the sealed e2dd preflight, eligible controls, and exactly
one post-window sealed gate. Full CPU model/family/flags/XCR0, libc identity and
resolved memory offsets, affinity, reported topology, frequency availability,

Its per-binary original manifest is checked. No archived executable or script
is run locally. Fresh measured VMs execute only the declared sealed normal,
new owned-source companion and compiled public metadata probe.

Only a corresponding **confirmed final-summary** 1024 DATA or prepared-H
failure in the sealed preflight (normal exit 101) triggers its triplet. A first
LEAK/max-t line is insufficient. A 2049-only or H128-only failure is retained
but does not trigger these controls. Nonreproducing hosts are inconclusive,
not replacements or passes closing previous failures. The single post-window
gate cannot trigger controls retrospectively and is never repeated to regain

Each triplet needs its own literal companion row to co-reproduce the

## Six rows and retained storage

DATA and prepared H each have three rows, seeds 0 and 1:

1. `literal`: the original class-dependent producer, original bytes and whole
   group allocations. DATA generates random 1024 bytes for both classes and
   fixed alone adds a zero clear. Prepared H fixes H=0 with no RNG/heap work;
   random makes the original random 16-byte Vec, converts it and constructs
   a key before the timed interval.
2. `identical_history`: DATA uses a once-opaque byte mask fixed=FF/random=0
   before its original generated byte stores, then keeps only the original
   fixed extra clear at that actual Vec. Fixed therefore preserves its
   random-to-zero history; both final timed byte sequences are zero. Prepared
   H retains the original random temporary and opaquely observes its completed
   Vec before conversion; it masks the resulting raw H to zero before the one
   key construction. Fixed retains the absence of RNG/heap work. Both branches
   execute added raw-H byte masking; there is no post-key overwrite/reprepare.
3. `equal_variable`: every class executes equal RNG/allocation/store work using
   a private replay RNG and once-opaque mask to produce the **exact frozen
   original** final input bytes/H. There is no class-0 extra clear or common
   post-store normalization pass. The scheduler remains independent so extra
   control work does not change later class order/H fixtures.

These are intentional counterfactuals. Added mask arithmetic/opaque observation,
changed random-class initial values, fixture metadata work and changed code
layout can perturb preparation state. Matching RNG advances, original store
width and unrolling does not establish identical complete prior state.
The prepared-H completed-Vec observation also forces metadata reload/checks
and can add conversion/copy bookkeeping on the random branch. Those operations
are part of the counterfactual perturbation, not exact original state matching.

The original reference names determine the RNG seed (including name length):
`ghash [Portable] batch 1024 data: 0 vs random` and
`ghash [Portable] batch 1024 prepared H: 0 vs random`.
Warmup and every measured batch's class/RNG-before/H fixtures are retained for
both seeds. Literal fixtures are reconstructed only after the entire timed
batch; equal-work fixture precomputation is labeled a different allocation
history. Unit checks compare both schedules and continuing RNG prefixes.
The CSV `fixture_h_value` is meaningful for the original KEY fixture only;
DATA uses an unused zero sentinel in that column. Actual DATA uses the original
nonzero fixed H documented in its source fixture, not that sentinel. The KEY
identical-history row transforms the original fixture H to zero before key
construction; the column still records the original fixture, not an inspection
of the retained prepared key.

The actual input storage is `Vec<Vec<Vec<u8>>>` for DATA or
`Vec<Vec<GhashKey>>` for prepared H (one input per group). Vec header size is
24 bytes and key size/stride is 1712 bytes. Metadata is separate from these
objects. Prepared H shares one 1024-byte 0x5a Vec, with no per-key data clone.
DATA uses the same original fixed H and AAD `aad`. Each triplet uses one shared
non-inlined timed helper. Both input/key are borrowed. Input/key construction,
owned moves, retained-key Drop/wipe and Vec deallocation remain outside both
clock reads. Hash-internal accumulator/working-buffer cleanup and the original
Copy 16-byte tag observation remain **inside**. Addresses are observed after
the stop timestamp, and all retained group objects are dropped outside timing.

Clock quantization must be native (tick=0, no coarse clock/forced repetitions);
there is one call per sample. The unchanged paired statistic, crops, threshold
4.5 and repeat judge remain. Stages do not fence pending stores/cache/upper
register history, and separate row medians must not be subtracted as an
instruction-latency decomposition.
