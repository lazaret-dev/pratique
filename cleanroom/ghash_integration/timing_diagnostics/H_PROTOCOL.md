Rows 1–7 are fixed before measurement:

1. Literal original-generator full constructor, 128-byte hash and destruction. It retains class 0's fixed-array route and class 1's original 16-byte RNG/Vec route, data cloning and nested input allocation. Fixture verification occurs after each timed batch, so it does not precompute a different input allocation history for this row. Added observation still changes the harness surroundings.
2. Identical zero H with the original class-specific generation history. Class 1 retains RNG/allocation/normal byte stores, with an opaque zero mask applied before those stores; class 0 retains the literal fixed array. There is no common final overwrite. The actual H and address are recorded. Optimized producer code must retain these operations.
3. Equal-work H0/random generation with the exact original fixtures. Each class does 16 RNG updates, one Vec allocation and normal stores; masking occurs before each store. This is a counterfactual with precomputed fixtures, not the original history. A private replay RNG starts from the recorded fixture state and cannot affect future input selection.
4. Fresh prepared-key 128-byte hash only. Each sample constructs a fresh key before its start timestamp and destroys it after its stop timestamp. This per-sample setup and its storage/cache history are explicit; it is not asserted identical to the original whole-batch preparation history.
5. Constructor/preparation and destruction, with no hash. A fresh local key leaves scope before the stop timestamp.
6. Constructor/preparation only. An explicit retained local receives the existing constructor result, is observed, and stays alive through the stop timestamp. Cleanup occurs afterward. The constructor's return and retained-storage moves are timed. A tracked destructor unit check verifies stop-before-cleanup; optimized code must verify the actual production-key boundary. Returning a value through the original generic timer would include its destruction and is deliberately not used.
7. Fresh in-place wipe only. Construction happens before the first timestamp, and one in-place wipe is timed. The normal final destructor and its second wipe happen after the stop timestamp. Every sample gets a fresh object; a wiped object is never retimed.

Rows 3–7 use the same equal-work fixture replay. A separate negative control uses identical H and equal-work generation for the same full operation. A known-leak positive control has that same full operation plus a class-specific dependent delay calibrated to about 2% of its cost; both the target and final measured delay costs and their ratio are retained. The bounded calibration is healthy only if its final ratio is 1.5–2.5% and the known leak is detected on both seeds. The existing one-percent sensitivity and early-exit controls also run. Every outcome is explicit, including control failures. Collection exit success does not mean a timing gate passed. Drop-only row 8 is deferred; no Option/take move experiment is introduced.

Stage names identify code between timestamps, not completion of all earlier stores. No hardware fence is added. Fresh construction immediately before the hash-only or wipe-only timer may leave class-dependent cache, store-buffer or upper-register history. A flagged stage therefore does not automatically identify that operation's instruction latency. Medians from these separate rows must not be subtracted as a causal decomposition.

Every measurement uses a native fine clock and exactly one call per sample, rejects any nonzero forced clock tick and an incompatible forced-repetition setting, and retains raw duration, class, input/H/data/key addresses where observable, batch, sample, actual H, original fixture H and replay state. Temporary key addresses that cannot be observed without changing their storage are zero with the documented meaning "unobserved." `timed_address` is the retained key address when observed (rows 4, 6 and 7), and otherwise the constructor's input-H address; it never purports to identify an unobserved temporary. Hash input data has its separate recorded address. Address and fixture observations occur after the stop timestamp.
