## Known limitations (by design, for now)

- `unsafe` appears only behind the `net` feature (the pure verification part is `forbid(unsafe_code)`): in the SIMD kernels (AES-NI/ARMv8 AES and carry-less multiply in `aes_hw.rs`, GHASH, and the ChaCha20 vector backends), the operating-system random calls in `crypto::rand`, the calls into the systems' certificate-store libraries in `native_roots` (B-101), the one `recv` with `MSG_PEEK | MSG_DONTWAIT` in `asyncio::net` (B-90), the volatile write in `util::Zeroize`, and the two instructions that set and read ARM's `DIT` bit around the secret arithmetic (`crypto::dit`, B-99); each has a SAFETY comment. Building with `RUSTFLAGS="--cfg pratique_portable"` removes the SIMD kernels. Nothing in parsing, X.509, ECDSA, RSA or the TLS state machine uses it (B-77 makes that checkable with `forbid(unsafe_code)`).
- Each connection holds a 64 KiB receive buffer and, while writing, up to about 66 KiB of write buffer (an HTTP/2 connection also has a 128 KiB read buffer in its reader thread).
- HTTP/1.1 by default (ALPN offers `http/1.1`); HTTP/2 only when asked for with `Client::http2(true)`, and only for the blocking client (and the `*_async` methods that run it), not for `AsyncClient` (B-72 part 2). Connections are reused (a keep-alive pool; one shared connection per origin for HTTP/2). HTTP/2 responses have no reason phrase and their trailers are dropped; server push is refused and priorities are ignored. Responses are decoded (`gzip`, `deflate`) only when asked (`decompress`, B-37); plain-http requests are refused unless `allow_insecure_http(true)`; proxies are used for https URLs only.
- An HTTP/2 connection reads and decrypts on one thread (about 170 MB/s on the test machine), and may hold up to its 32 MiB connection window of body that the application has not read yet. It costs two threads for as long as it is open.
- The TLS and HTTP/2 server (`server` feature) is a test peer, not a product: Ed25519 signing that is not constant time, resumption only from tickets it keeps in memory (B-35), no client certificates, one certificate, no review (B-83).
- TLS 1.3, and TLS 1.2 with a server that speaks nothing newer (ECDHE and AEAD suites only, the extended master secret required, no renegotiation, no resumption; B-36), unless the client or the request asks for 1.3 only; key exchange with X25519, P-256 or P-384 (in 1.3 a share for the first, the others after a HelloRetryRequest); no client certificates (an empty Certificate is sent when asked); session resumption in TLS 1.3 only, and never 0-RTT (B-35).
- Revocation is checked with a stapled OCSP response, CRLs that are supplied or fetched, and, when asked for (`Revocation::with_ocsp_source`, B-63), the certificate's OCSP responders; by default only the staple is used, so soft-fail is blind to a revoked certificate on a server that does not staple unless a source is configured (B-63, B-64).
- Trust roots come from a PEM bundle file by default (on Windows, the certificate store when there is no file); the operating system's own store, the macOS Keychain's trust settings or the Windows store, is read when asked for (`ClientConfig::with_native_roots`, B-101).
- No cache of chain validations: every full handshake checks the server's chain. B-88 (a cache for a leaf and issuer until the earlier of their ends, as a `Client` option) was dropped on 2026-10-08, for B-49's reasons: resumption (B-35, B-47) already skips the check on a host's repeat connections, where a cache would pay, and a cache keyed on everything that can change a verdict (the trust store's contents, the clock, the purpose, the revocation policy and evidence) is a new place to be wrong in the accepting direction, to save about 0.15 ms.
- A connection that ends without `close_notify` is reported as an error (truncation protection).
- Unaudited cryptography; not for production use with sensitive data until B-23 (independent review) is done.
